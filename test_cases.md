# Matriz de Pruebas: Feature Extensión de Reservaciones

| ID | Nombre del Caso | Tipo de Caso | Precondiciones | Entrada (Payload / Parámetros) | Pasos | Resultado Esperado | Resultado Obtenido |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **TC-01** | Extensión exitosa sin traslapes | **Happy Path** | - Reservación existente con ID válido.<br>- Estado `ACTIVE`.<br>- Hora actual < `endTime` (vigente).<br>- Espacio libre después de `endTime`. | URL: `PATCH /api/reservations/:id/extend`<br>Body: `{"endTime": "2026-10-13T13:00:00.000Z"}` | 1. Usuario hace clic en "Extender".<br>2. Captura hora posterior libre.<br>3. Envía el formulario.<br>4. Backend valida y persiste. | **HTTP 200 OK**<br>- Objeto reservación retornado con nuevo `endTime`.<br>- Base de datos actualizada.<br>- Frontend muestra notificación de éxito y refresca la lista. | **Pass**: Reservación actualizada a las 13:00:00Z en MongoDB y reflejada en la interfaz. |
| **TC-02** | Fecha/hora con formato corrupto o inválido | **Error Case** | - Reservación existe, está `ACTIVE` y vigente. | Body: `{"endTime": "fecha-invalida"}` | 1. Se envía solicitud con formato no parseable por `Date`.<br>2. Ejecución de `validateExtensionEndTime`. | **HTTP 400 Bad Request**<br>- Mensaje de error descriptivo.<br>- Base de datos intacta. | **Pass**: Retorna `400` con mensaje de error de fecha inválida; sin cambios en BD. |
| **TC-03** | Nueva hora final anterior al fin actual | **Error Case** | - Reservación actual finaliza a las `12:00:00.000Z`.<br>- Está `ACTIVE` y vigente. | Body: `{"endTime": "2026-10-13T11:00:00.000Z"}` | 1. Se ingresa una hora anterior al `endTime` vigente.<br>2. Backend evalúa `newEnd <= currentEnd`. | **HTTP 400 Bad Request**<br>- Rechazo de la solicitud sin modificar la reservación. | **Pass**: Retorna `400`; la regla de horario rechaza la reducción de tiempo. |
| **TC-04** | Nueva hora final idéntica a la actual | **Error Case** | - Reservación finaliza a las `12:00:00.000Z`. | Body: `{"endTime": "2026-10-13T12:00:00.000Z"}` | 1. Se ingresa exactamente el mismo `endTime`.<br>2. Backend valida la condición de incremento estricto. | **HTTP 400 Bad Request**<br>- Rechazo por duración nula de extensión (`newEnd <= currentEnd`). | **Pass**: Retorna `400`; requiere que la hora sea estrictamente posterior. |
| **TC-05** | ID de reservación inexistente o mal formado | **Error Case** | - El ID no corresponde a ningún documento en MongoDB o falla `isValidObjectId`. | URL: `PATCH /api/reservations/64f1a2b3c4d5e6f7a8b9c0de/extend`<br>Body: `{"endTime": "2026-10-13T14:00:00.000Z"}` | 1. Se invoca el endpoint con ID inexistente.<br>2. `Reservation.findById` devuelve `null`. | **HTTP 404 Not Found**<br>- Mensaje indicando que la reservación no fue encontrada. | **Pass**: Retorna `404` con mensaje `"Reservation not found"`. |
| **TC-06** | Intento de extender una reservación ya vencida | **Error Case** | - Reservación existe con estado `ACTIVE`.<br>- Hora actual (`now`) es posterior a `endTime`. | Body: `{"endTime": "2026-10-13T15:00:00.000Z"}` | 1. Se intenta extender una reserva expirada.<br>2. Backend evalúa `reservation.endTime <= now`. | **HTTP 409 Conflict**<br>- Rechazo porque solo reservas vigentes son extensibles. | **Pass**: Retorna `409` con mensaje `"Only active and unexpired reservations can be extended"`. |
| **TC-07** | Intento de extender una reservación cancelada | **Error Case** | - Reservación existe con estado `CANCELLED`. | Body: `{"endTime": "2026-10-13T15:00:00.000Z"}` | 1. Se solicita extensión sobre reserva cancelada.<br>2. Backend evalúa `status !== 'ACTIVE'`. | **HTTP 409 Conflict**<br>- Rechazo por estado no elegible. | **Pass**: Retorna `409` bloqueando la operación. |
| **TC-08** | Conflicto con otra reservación activa en el mismo cajón | **Error Case** | - Reserva A finaliza a las 11:00.<br>- Existe Reserva B activa en el mismo cajón de 11:30 a 13:00. | Body: `{"endTime": "2026-10-13T12:00:00.000Z"}` | 1. Usuario intenta extender Reserva A hasta las 12:00.<br>2. Backend busca traslapes con `hasTimeConflict`. | **HTTP 409 Conflict**<br>- Rechazo por solapamiento con la Reserva B.<br>- Horarios de ambas reservas permanecen intactos. | **Pass**: Retorna `409` con mensaje de conflicto de horario en el cajón. |
| **TC-09** | Adyacencia exacta con inicio de siguiente reserva activa | **Edge Case** | - Reserva A finaliza a las 11:00.<br>- Reserva B activa inicia a las 12:00 en el mismo cajón. | Body: `{"endTime": "2026-10-13T12:00:00.000Z"}` | 1. Se extiende Reserva A exactamente hasta las 12:00.<br>2. Backend evalúa colisión en frontera (`12:00 > 12:00 = false`). | **HTTP 200 OK**<br>- Se permite la extensión.<br>- Ambas reservas quedan contiguas sin colisión. | **Pass**: Retorna `200`; se permite adyacencia de fin e inicio sin traslape. |
| **TC-10** | Traslape contra reservación con estado CANCELLED | **Edge Case** | - Existe una reservación previa en el mismo cajón de 11:00 a 13:00 pero con `status: 'CANCELLED'`. | Body: `{"endTime": "2026-10-13T12:30:00.000Z"}` | 1. Se extiende la reserva activa cubriendo el horario cancelado.<br>2. Query filtra únicamente `status: 'ACTIVE'`. | **HTTP 200 OK**<br>- La reserva cancelada es ignorada.<br>- La reserva activa se extiende exitosamente. | **Pass**: Retorna `200`; registros cancelados no generan bloqueo. |
| **TC-11** | Exclusión de auto-conflicto con el rango original | **Edge Case** | - Reserva A va de 09:00 a 11:00.<br>- Se extiende de 11:00 a 12:00. | Body: `{"endTime": "2026-10-13T12:00:00.000Z"}` | 1. Backend evalúa posibles colisiones en el cajón.<br>2. Query utiliza `{ _id: { $ne: reservation._id } }`. | **HTTP 200 OK**<br>- El tramo 09:00 - 11:00 de la misma reserva no se autodetecta como conflicto. | **Pass**: Retorna `200`; la reserva en mutación no colisiona consigo misma. |
| **TC-12** | Extensión en el milisegundo límite de vigencia | **Edge Case** | - La hora actual está a milisegundos de alcanzar `endTime`. | Body: `{"endTime": "2026-10-13T13:00:00.000Z"}` | 1. Petición entra justo cuando `endTime <= now`.<br>2. Backend evalúa la condición de expiración. | **HTTP 409 Conflict**<br>- Rechazo seguro en el límite estricto de expiración. | **Pass**: Retorna `409` consistente al expirar el tiempo de tolerancia. |
